# 啟用手機與電腦共用

程式已支援 Supabase，但必須先建立你自己的專案並部署新版網站，才有正式雲端同步。以下動作在你的 Supabase／網站部署後台完成；不要在聊天中提供密碼或 secret 金鑰。

## 1. 建立 Supabase 專案

1. 到 [Supabase](https://supabase.com/) 建立專案，選擇適合你的區域。費用、免費額度與閒置專案政策，以官方目前方案為準。
2. 在專案的 SQL Editor 執行本專案的 [`supabase/schema.sql`](../supabase/schema.sql)。這會建立 `lily_workspaces`、登入帳號隔離的 RLS 規則，以及帶版本檢查的儲存函式。
3. 在 Authentication 設定啟用 Email 登入，保留 Email 確認功能。在 URL Configuration 設定新版網站的正式 HTTPS 網址為 Site URL。
4. 從專案 Connect／API 設定取得 **Project URL** 與 **publishable key**（舊版可用 `anon` key）。這兩項是網頁可公開的連線資訊。**不要將 `service_role`、`sb_secret_…` 或資料庫密碼放進網頁。**

本專案不需要 Supabase 的管理員金鑰。資料使用者由登入的 access token 決定，資料庫 RLS 仍須啟用。

## 2. 將公開設定加入網站

建議部署時提供以下建置環境變數：

| 名稱 | 用途 |
| --- | --- |
| `SUPABASE_URL` | 專案 HTTPS 網址，例如 `https://專案代碼.supabase.co` |
| `SUPABASE_PUBLISHABLE_KEY` | 公開 publishable key |
| `SUPABASE_ANON_KEY` | 僅在使用舊版 anon key 時，取代上一項 |

執行 `npm run build` 後，公開設定會寫入 `dist/src/cloud-config.js`，不會改寫原始碼中的設定。將 **整個 `dist/`** 部署至 GitHub Pages 或其他靜態網站服務。只設定環境變數但未重新建置／部署，不會更新已上線的網站。

本機開發也可以開啟畫面上方「登入同步」，在「專案連線設定」輸入兩項公開設定。這種設定只保存在目前瀏覽器；若沒有部署預設設定，每台裝置都要填一次。可接受標準 `*.supabase.co` HTTPS 網址，尚未支援自訂 Supabase API 網域。

若需從 Codex 雲端環境連線驗證，請在環境網路設定加入**你的專案完整網域**，例如 `專案代碼.supabase.co`。尚未知道實際專案網域前，不需要加入整個萬用網域。

## 3. 登入並搬入既有資料

1. 在新版網站「登入同步」註冊帳號，按信箱驗證信完成驗證，再使用相同 Email 與密碼登入。密碼只傳送到已設定的 Supabase，不會放入備課資料或 JSON 備份。
2. 第一次登入時，本機備課與雲端帳號資料分開保存，不會自動上傳或覆蓋。先匯出既有備課，再按「搬入這台裝置原本的備課」，確認搬入。
3. 等狀態變成「已同步到雲端」，在另一台裝置開啟**同一個新版網站**，登入同一帳號。課表、動作庫、地點、學生、備註與練習進度就會共用。

Supabase 的預設寄信服務有收件對象／頻率限制；若要提供給其他使用者註冊，應依 [官方 SMTP 說明](https://supabase.com/docs/guides/auth/auth-smtp) 設定自己的寄信服務。沒有收到驗證信時，先檢查專案的 Auth 郵件紀錄、垃圾郵件及寄信設定；不需要關閉 Email 驗證來略過問題。

## 同步方式與資料保護

- 編輯先寫入這個帳號在目前瀏覽器的快取，約 0.7 秒後嘗試上傳。畫面顯示「已同步到雲端」才代表收到雲端儲存確認。
- 網站在前景時，每 20 秒檢查遠端更新；回到網站、恢復連線或按「立即同步」也會檢查。這是自動輪詢，不是即時協作游標。
- 建置版成功準備離線快取後，可在離線時重新開啟與編輯已保存的資料，恢復連線後重試。首次登入、取得尚未下載的課程及同步仍需連網。詳見 [iPhone／iPad 安裝說明](iphone-ipad.md)。
- 同時編輯會以資料庫版本檢查阻止覆蓋。若兩邊不同，會停下來讓你選擇「雲端版本」或「目前版本」，不會自動合併。取代前會在此帳號的本機快取保留雙方備份，可下載為可匯入的 JSON。
- 登出後回到原本本機資料；不同帳號的快取不會自動混用。登入狀態與帳號快取保存在瀏覽器中，在共用電腦使用完應登出。尚未同步的資料在清除瀏覽資料時仍可能遺失。
- 支援 Web Locks 的瀏覽器會限制同一帳號在同一個瀏覽器只開啟一個備課分頁，避免共用快取互相覆蓋；手機與電腦可同時登入。其他瀏覽器請避免同時開啟多個備課分頁。
- 所有課程目前共用一份帳號工作區（上限 10 MB），適合個人備課；尚未實作多人團隊共編、附件影片上傳或課程出席收費。
- 可定期匯出 JSON 備份，備份含學生紀錄，但不含登入 token、密碼或 Supabase 管理員金鑰。

## 上線驗證

建立真實專案後，務必完成以下檢查，再把它當作正式資料保存位置：

1. 用兩個不同 Email 建立測試帳號，確認各自只能看到自己的課程。
2. 同一帳號在手機建立課程，確認電腦登入後可讀取；在電腦改動，再確認手機可取得更新。
3. 兩台同時編輯，確認出現版本衝突；下載備份後再選擇保留版本。
4. 測試離線編輯、恢復網路、登出與重新登入，並保留一份匯出備份。

儲存 Supabase 設定、在 Codex 發布開發環境、以及部署正式網站是三件不同的事。此處沒有自動建立專案、執行遠端 SQL 或發布網站。

## 開發測試

`npm test` 包含使用模擬 Supabase HTTP 回應的同步測試。開發伺服器啟動後可執行 `python3 tests/browser_cloud.py`，以獨立手機／桌面瀏覽器測試登入、搬移、離線、衝突與帳號分離。這些測試**不代表真實 Supabase、郵件寄送、部署或 RLS 已驗證**；正式驗證需要完成上方專案設定。
